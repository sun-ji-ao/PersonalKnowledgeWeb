# 技术笔记站：动态写作方案

## 产品目标
长文阅读与写作体验优先。原有 Markdown、以后上传的 Markdown 和在线写作，统一形成 HTML 正文并保存到 SQLite；阅读页面呈现已发布 HTML。Markdown 是导入格式及原件归档格式，转换成功后不再作为日常编辑和阅读的主正文。支持代码高亮、数学公式和 Mermaid 图表。UCloud 上的动态服务现通过 `https://sunjiao.me/` 直接提供公开阅读与私有写作，发布无需重新构建。原 GitHub Pages 保留为历史站点与 DNS 回退目标；静态导出不再是本次上线的依赖。

## 架构

第 6 批已实现媒体私有存储/发布引用权限、缺图 CAS 修复、同修订分类、持久纯文本检索、RSS/sitemap 及阅读工具。针对性和独立集成自动化通过；4315 隔离合成实例的浏览器验收随后完成。见 [第 6 批报告](./BATCH-06-ACCEPTANCE.md)、[浏览器记录](./BATCH-05-06-BROWSER.md)与[运行说明](./HTML-MEDIA-SEARCH-GUIDE.md)。

数据库费用约束（2026-09-23）：优先免费、无需订阅的数据库。沿用已实现的 SQLite，数据库软件费用为零，不依赖云服务免费额度；部署必须保留持久化数据目录并安排备份。服务器和存储成本另行评估。

- 独立目录中的 JavaScript 项目，不修改原有 Astro 项目。
- Node.js 24 HTTP 服务 + SQLite 中的 HTML 正文 + 私有来源归档/附件目录。HTML 存在数据库 TEXT 字段即可满足 HTML 存储，不强制每篇文章另存 `.html` 文件。
- 版本记录区分 `html_source`（可编辑的规范 HTML，正文唯一真源）和 `html_rendered`（由该版本生成的展示 HTML），文章通过草稿版本和发布版本引用管理可见性。
- Markdown 导入先解析 frontmatter、建立资源映射，再转换为语义 HTML，经规范化与清洗后入库。在线写作提交 HTML，走相同规范化、清洗和存储流程。
- HTML 编辑器保留代码语言和代码原文、公式 LaTeX、Mermaid 源码等语义。高亮 span、KaTeX DOM 和图表 SVG 是展示产物，不能成为唯一的可编辑内容。编辑器 JSON 可辅助恢复，但不能代替 HTML 主正文。
- 阅读使用已发布版本的 `html_rendered`；更换转换器或展示规则时，通过显式版本化任务生成待检查的新版本，不从归档 Markdown 自动覆盖在线修改，也不随部署静默改写文章。
- 单作者密码登录，HttpOnly 会话；默认只绑定本机。公开阅读与后台写作分开。
- 草稿与已发布内容分离：编辑已发布文章不会立刻泄露未发布内容。
- SQLite 记录版本号，冲突时拒绝覆盖其他页面的修改；保存状态可见。
- HTML 版本与文章引用通过数据库事务提交；渲染失败时仍允许保存有效的语义草稿，但不得覆盖旧发布版本。发布必须指向验证通过的同一版本正文、展示内容、目录和媒体引用。
- 来源归档及附件先写临时文件、校验并移入私有受管理目录，再提交数据库引用；失败不删除原件，未引用文件延后核查。不能将私有原件或草稿附件目录直接公开。
- SQLite、归档 Markdown 和附件组成联合备份；搜索索引和展示产物可从 HTML 正文重新生成。

## 迁移路线
原项目约 253 篇 Markdown 使用本地批量工具调用统一转换核心，在隔离数据目录建立 HTML 草稿和转换报告；先抽样，再全量。原文件按原字节归档并记录哈希，frontmatter 保存来源信息，图片及旧链接按映射转换。MVP 数据库迁移与旧文库迁移是两类来源：分别处理现有草稿与已发布快照，避免把未发布修改转成公开内容；不能把两类来源简单叠加计入 253 篇。转换通过后 HTML 成为日常正文，Markdown 原件可追溯下载。迁移前备份，验证前保留旧字段和原库。详见 [转换流程与验收](./HTML-CONTENT-DESIGN.md)。第 7 批已实际执行隔离迁移与两套联合恢复；原默认库没有原地升级，旧文没有自动发布。后续从恢复副本发布 253 篇并部署至 UCloud，详见 [b9 部署状态](./B9-DEPLOYMENT-STATUS.md)。最终产物路径与两篇内容修订见 [迁移报告](./BATCH-07-ACCEPTANCE.md)，操作见 [批迁移指南](./HTML-BATCH-MIGRATION-GUIDE.md)。
