# 第 3、4 批跨批集成验收

日期：2026-09-23。负责人：集成代理。当前状态：跨批接口和自动化验收完成，最终独立集成测试 27/27 通过。公开 HTML 阅读属于第 5 批，本报告不声明已上线。

## 边界与统一接口

- 第 3 批负责 HTML SQLite 修订、私有原字节归档、幂等导入、迁移和联合备份；第 4 批负责显式启用的 HTML 服务与可视化编辑器。
- HTML 实验入口必须使用 `HTML_EDITOR=1` 和显式隔离 `DATA_DIR`；旧 Markdown API 保留。不得写默认数据目录、正式迁移、部署或提交 Git。
- `htmlSource` 为唯一编辑真源；展示 HTML 与编辑器 JSON 均不能反向替代它。文章版本用于 CAS，修订不可变；恢复历史创建新修订，只更新草稿引用。
- 上传使用原始请求字节；归档下载受认证保护。来源键与字节哈希用于幂等；在线编辑后的同源重导不能覆盖当前草稿。
- 实际接口：`/api/html/notes`、`/api/html/notes/:id`、`history`、`restore`、`export`、`/api/html/import`、`/api/html/archives/:id`、`/api/html/normalize`。保存输入 `htmlSource`，笔记输出沿用存储字段 `html_source`；恢复输入 `{revisionId,version}`。上传返回 `{note,unchanged,archive}`。
- 服务支持 `HTML_DB_PATH`、`HTML_ARCHIVE_DIR` 指定迁移/恢复产物；仍须显式隔离 `DATA_DIR`，且默认真实数据目录、符号链接实际指向及 Windows 大小写变体受保护。

## 已识别的衔接风险

1. 原服务器 JSON 上限 2 MB，小于规范 HTML 11.4 MB 上限；HTML 接口需独立限额并考虑 JSON 转义膨胀。
2. 原浏览器上传使用 `file.text()`，不能用于新原字节归档入口。
3. 编辑器 schema 必须完整覆盖 notes-html/1；仅支持常见段落、代码和公式不足以完成旧文往返。
4. 旧 `publish()` 复制 Markdown 字段；新 HTML 修订不能意外进入旧发布路径或从草稿拼接公开内容。
5. 展示失败允许保存合法语义草稿，但不得把失败修订标记为可发布。

## 实际命令与结果

从 `technical-notes-lab` 运行；每个服务器使用临时 `DATA_DIR`，测试结束关闭并清理。

- `node --test --test-name-pattern='authenticated HTML|byte upload' test/batch34-integration.test.mjs`：2/2 通过，约 7.9 秒。覆盖两请求同版本竞争、重启、字节上传、同源新版本、在线冲突、恢复原件引用、匿名隔离与非法 UTF-8。
- `node --test --test-name-pattern='render errors' test/batch34-integration.test.mjs`：1/1 通过，约 3.1 秒。非法公式仍保存源正文及诊断，不可发布；HTML normalize 接受超过旧 JSON 2 MB 限制的 2.1 MB 正文。
- `node --test --test-name-pattern='canonical contract' test/batch34-integration.test.mjs`：首次揭示 table 单元格块内容、details 直接文本、空容器被编辑器改变；代理 2 修复后 20/20（含父测试）通过，约 18.2 秒。
- 后续加测发现根级行内片段被自动包段落，且等价嵌套标记重新排序会误触发严格字符串 guard；已通知代理 2。标记重排本身不算语义损失，对应测试比较文本标记集合与链接属性。
- 最终 `node --test test/batch34-integration.test.mjs`：退出码 0，27 通过、0 失败/跳过，55,153.8457 ms。上述结构与 guard 问题已修复；新增联合恢复测试通过，实际使用 `HTML_DB_PATH` 和 `HTML_ARCHIVE_DIR` 启动恢复后的服务器。

最终 27 项含 21 个 schema 子场景及父测试、两项存储 HTTP 工作流、一项展示失败与体积边界、一项联合恢复 HTTP 续编、一项 guard 语义损失拒绝。schema 测试执行真实 ProseMirror 文档加载、普通文字事务编辑、序列化、服务同源规范化、再次加载与序列化；与 HTTP/存储测试分别承担不同边界。

联合恢复实际验证：运行中 SQLite 一致性快照、归档字节和附件字节；备份后继续修改源库，恢复仍取得快照时草稿；重新启用服务后下载原件及继续保存成功，历史追加而发布引用保持原修订。没有依赖重新导入 Markdown 恢复草稿。
