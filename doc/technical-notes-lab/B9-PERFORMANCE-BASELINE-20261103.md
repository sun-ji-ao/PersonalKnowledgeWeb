列表公网首字节分别为 0.989、1.275、1.164 秒，完整下载却为 11.140、24.676、25.583 秒。结合服务器本机耗时，可判断大响应传输是该接口当前主要开销之一；不能据此确定带宽限制来自哪段网络，也不能把这个接口的下载时长当作首页加载时长。首页是服务端 HTML，不会在浏览器中额外请求该 JSON 列表。

公开列表 GET 响应的 Content-Type 为 application/json; charset=utf-8，未出现 Content-Encoding；即使 curl 请求压缩，下载字节数仍与原始 JSON 一致。首页传输字节数较原始响应明显减少。

## 代码与数据证据

- 当前公开列表有 253 篇，完整返回 16,487,671 字节，包含每篇 html_rendered 与 headings。
- 同一响应仅保留 id、revision_id、title、description、tags、category、created_at、published_at，紧凑 JSON 为 80,677 字节，约减少 99.5%。这是内存中投影的估算，尚未实现或上线新接口。
- 对同一原始响应进行一次内存 gzip level 6 压缩得到 1,404,772 字节。该值不是当前线上压缩效果，也不包含线上压缩 CPU、缓存和并发成本。
- lib/html-store.mjs 的 publicList 先查询全部已发布 ID，再逐篇 publicGet；每篇还加载完整展示正文与目录。253 篇时这段代码执行 1+253 次查询。
- server.mjs 的首页、搜索、RSS、sitemap 等调用 publicList，虽然它们主要使用摘要或索引，也先加载完整正文。搜索已使用 revision_search 持久化纯文本，并不需要为了全文匹配重新加载展示 HTML。
- 未在 public/ 客户端代码中找到对完整列表接口的直接调用；测试及恢复脚本仍使用它，不能未经兼容评估直接删除字段。
- 服务器与本地 server.mjs 哈希一致：ab899a94768b8e19f43d5198c55e6cff13b5720be84e5f5ee6ece29d0280c759。
- 服务器与本地 lib/html-store.mjs 哈希一致：2e7b1562f3e86ee9886f5246909192db355344a339eecb5e7fbd4c0d978bd4cc。

## 下一批实施范围

1. 新增仅查询已发布元信息的 JOIN 查询，供首页、分类、RSS、sitemap 使用；搜索继续走既有正文索引，避免加载全部展示 HTML。
2. 增加明确的摘要列表入口或显式摘要参数，保留现有完整列表契约；若做分页，定义排序、总数、页边界和筛选行为，覆盖发布/撤回可见性。
3. 独立评估仅限网站作用域的 JSON 压缩，不改其他共存服务。压缩可减少传输，但不能代替轻量查询。
4. 先在隔离数据上比较结果一致性、查询开销、响应字节和发布后可见性，再重复相同采样。暂不引入需要失效管理的缓存。
5. 当前部署工具对 server.mjs、html-store.mjs 等设有哈希兼容门槛。本次优化会触及这些文件，须完成独立兼容性复核与升级/旧版恢复验收后制定上线方式，不能为了部署跳过该门槛。
