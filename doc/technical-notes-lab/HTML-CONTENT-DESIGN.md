统一以规范 HTML 为正文真源，存入免费的 SQLite。来源包括旧 Markdown、网页上传 Markdown、在线可视化写作。原始 Markdown 按原字节私有归档，保留来源和恢复依据；作者后续修改以 HTML 为准，不保持两套可编辑主正文。

采用“一套转换核心、两个导入入口”：旧文章在本地批量迁移时转换，日常上传在应用导入时转换。部署负责发布应用代码和执行受控的数据库结构升级，不进行隐式全库正文转换。公开阅读直接读取已发布 HTML。

## 2. 转换时机比较

| 方案 | 适用情况 | 本项目决策 |
| --- | --- | --- |
| 另写完全独立的转换程序 | 一次性离线输出 HTML | 不建立第二套解析规则；提供独立可运行的 CLI 入口，但复用应用转换核心 |
| 本地批量迁移时转换 | 已有 253 篇文件，可以检查日志、图片与差异 | 采用；预检查、抽样转换、全量隔离转换、验收后迁入 |
| 每次部署时转换 | 以源文件驱动构建的发布流程 | 不作为日常路径；会把发布应用与发布内容耦合，也可能覆盖在线修改 |
| Markdown 上传导入时转换 | 作者日常上传一篇或多篇文章 | 采用；小文件同步处理，有界批量任务可重试且记录状态 |
| 每次阅读时转换 | Markdown 始终是真源的系统 | 不采用；本项目已要求 HTML 主正文，阅读只使用发布版本 |
| 在线 HTML 保存时规范化 | 可视化编辑器产生 HTML | 采用；不再绕行 Markdown，保存 HTML 草稿并生成预览/展示版本 |

## 3. Skill 选择与使用边界

本机技能目录及插件目录没有找到这两个 skill。本次读取源仓库中的 SKILL.md，选择并应用 `github/awesome-copilot` 的 `markdown-to-html` 作为转换流程设计参考，没有执行远端脚本或安装全局 skill。

| Skill | 已核验定位 | 采用方式 |
| --- | --- | --- |
| [markdown-to-html（github/awesome-copilot）](https://github.com/github/awesome-copilot/blob/main/skills/markdown-to-html/SKILL.md) | 涵盖 CLI、Node.js、自定义转换、批量处理及 HTML 清洗指导 | 主参考：统一单篇/批量流程，保留代码结构，明确转换后清洗；不强制换用示例中的 marked |
| [baoyu-markdown-to-html（JimLiu/baoyu-skills）](https://github.com/JimLiu/baoyu-skills/blob/main/skills/baoyu-markdown-to-html/SKILL.md) | 侧重公众号兼容主题与内联 CSS；当前描述含 Mermaid 经浏览器转 PNG，也允许关闭该处理 | 保留为以后公众号/独立排版导出的候选；不直接把带主题输出作为可编辑正文 |

选择依据是流程与当前应用匹配。Skill 是开发指导，不是需要在用户每次上传时调用的在线 AI 服务。实际转换由应用内固定版本代码完成，正文不会为转换而发送给第三方。

HTML 链路已实现独立 html-core 语义转换/清洗与 html-render 展示生成，由 html-content 的 Worker 包装提供时间和内存边界；继续使用固定版本 unified/remark/Shiki/KaTeX 等依赖。旧 lib/content.mjs 仅保留 Markdown MVP，renderMarkdown() 的高亮和公式展示结构不能作为可视化编辑器的规范源 HTML。

## 4. 存储规则

| 内容 | 保存方式 | 职责 |
| --- | --- | --- |
| `html_source` | SQLite TEXT，按不可变修订保存 | 可编辑、已规范化和清洗的 HTML，正文唯一真源 |
| `html_rendered` | SQLite TEXT，与源修订绑定 | 由同一版源 HTML 生成的阅读 HTML，可重建 |
| 标题、摘要、分类、标签 | 数据库版本记录及关联表 | 与正文一起形成发布快照，不能混入草稿字段 |
| 原始 `.md` | 私有归档目录，源字节不改写 | 下载原件、追溯转换、核对来源 |
| 图片与附件 | 私有受管理文件目录，数据库记录引用 | 根据发布/草稿引用控制读取 |
| 编辑器内部结构 | 可选的带版本辅助字段 | 提升重开与恢复体验，不能替代 HTML 主正文 |
| `.html` 文件 | 导出时生成或作为迁移检查产物 | 不要求与数据库保持第二套实时主存储 |

HTML 正文存数据库与 `.html` 文件存储都可行；选数据库可把正文、版本与发布引用放在同一事务，减少文件与数据库双写。数据库和归档/附件仍须联合备份。

拟增加 `content_revisions`、`source_archives`、`import_jobs/import_items`、`media/revision_media`、`legacy_urls`。文章持有 `draft_revision_id` 与 `published_revision_id`。每个修订记录源 HTML 哈希、转换/清洗/展示规则版本、生成状态、目录和搜索纯文本；展示失败不得标记可发布。

第 3 批实际新增独立 html_notes、content_revisions、source_archives、html_import_sources、html_legacy_migrations，不改旧 store 接口；有不可变历史、来源键幂等、版本冲突和明确迁移报告。第 6 批已补齐 revision_search 与 media/revision_media；第 7 批已增加来源清单、逐项/汇总报告、resume 和 legacy_urls 持久映射；未提供后台持久任务队列或旧 URL 运行时重定向。旧发布来源元数据在旧库中不存在，迁移明确标记不可恢复，不挪用草稿来源字段。

## 5. HTML 必须能够继续编辑

保存 HTML 不等于只保存最终网页截图或把页面 DOM 原样塞进数据库。正文只包含文章语义，站点导航、页脚、脚本和主题样式由模板提供。

- 代码：源 HTML 保留 `pre/code`、语言标识和转义后的代码原文；展示高亮是派生产物。
- 公式：使用受控语义节点保存行内/块级类型及原始 LaTeX；展示时生成 KaTeX，编辑时仍可读取公式源码。
- Mermaid：保留图表类型和转义后的源码；展示层生成图表，不把 PNG/SVG 当成唯一源内容。浏览器渲染的兼容方案需保留无脚本回退，若预生成 SVG 则在有界任务中处理并清洗 SVG。
- 标题、表格、列表、引用、链接与图片：限定可支持结构，给标题建立稳定锚点。
- 复杂块必须通过编辑器“加载→编辑→保存→重开”的往返测试。不能识别的节点显示兼容块或阻止破坏性保存，不能静默删除。
- 清洗只保留已定义标签、属性与协议；公式/图表源属性的允许范围显式配置。生成展示节点后还要使用匹配的输出策略校验，避免误删合法数学结构或放过注入。

## 6. 旧文章批量转换流程

1. 备份源库与当前数据库；建立来源清单，区分原始 Markdown、旧站生成稿和现有 MVP 文章。
2. 预检查编码/BOM、frontmatter、代码围栏、HTML 内嵌块、图片和内部链接；无法可靠解码的文件明确失败，不替换字符后继续。
3. 建立文章 ID、旧 URL、标题锚点及媒体映射。二阶段处理跨文章链接，避免目标尚未导入导致错误地址。
4. 原文归档，记录来源相对路径、源文件哈希及元数据。归一化用于解析的文本，不修改归档字节。
5. 统一转换为语义 HTML，规范化和清洗；生成阅读 HTML、目录、搜索文本与媒体引用。被移除或不支持的内容进入逐项报告。
6. 每篇文章和来源记录事务提交；批次汇总成功、失败、跳过与冲突。失败项目可单独重试；任务重试不能重复创建文章。
7. 相同来源与哈希重复导入直接识别；同源新内容若与在线编辑冲突，生成待合并草稿或冲突记录，不覆盖当前 HTML。
8. 先选择约 10 篇覆盖复杂内容的文章检查，再全量转换到隔离数据库；253 篇的成功、失败、跳过总数必须可对账。
9. 检查全文文本、代码/公式/图表源码、媒体与链接。HTML 字节不可能等于 Markdown 字节，不能用“输出哈希相等”判断转换无损。
10. 验收后再执行正式迁移；原 Markdown 保留归档，旧库和旧字段在回退窗口内保留。

单篇上传只有 `.md` 文件时，浏览器不会同时上传文件中引用的本地图片。界面应列出缺失资源并允许补传；服务器不能根据上传文本中的本地路径读取任意主机文件。批量工具也只能读取明确的导入根目录内资源，检查绝对路径、路径穿越、编码路径及符号链接。

## 7. 日常上传、写作和发布

```text
旧 Markdown 文件 → 本地批量迁移入口 ─┐
                                   ├→ 共用 Markdown→语义HTML 转换核心
网页上传 Markdown → 应用导入入口 ───┘           ↓
在线可视化编辑 → HTML ───────────────→ HTML规范化与清洗
                                              ↓
                                      SQLite：HTML草稿版本
                                              ↓
                                      生成/验证展示HTML
                                              ↓
                                    显式发布该修订的完整快照
                                              ↓
                                    阅读、搜索、RSS、导出
```

自动保存先保证合法源 HTML 落盘；展示生成可按需防抖处理，失败给出明确提示。正文、展示 HTML、文章元信息和媒体引用必须属于同一修订。发布只允许已完成校验的修订，修改草稿、渲染失败或撤回不得改变旧发布快照的内容。

来源 Markdown 下载只提供最初归档文件，并明确它不是在线编辑后的最新内容。当前内容默认导出 HTML。若以后增加“当前内容导出 Markdown”，必须标注这是格式转换结果，复杂排版可能不完全保留。

## 8. MVP 数据库迁移

当前实际字段为 `markdown`、`published_markdown` 等。迁移步骤必须与旧文库导入分开：

1. 备份，增加新表/字段，保留旧字段及 ID。
2. 分别把当前草稿 Markdown 和已发布 Markdown 转成不同的 HTML 修订；标题、摘要、标签等也分别使用对应版本的字段。
3. 未发布文章仍保持未发布；已有发布文章仅在原发布快照转换通过后切换读取引用，不能把最新草稿当成发布内容。
4. 来源若只剩数据库文本，归档该文本并标记来源为 MVP 数据库，不声称恢复了最初上传文件的原字节。
5. 对账并验证后启用 HTML 读写；转换失败的文章留在兼容路径并列出，不误报迁移完成。
6. 只有新写入数据已纳入回退导出后才考虑旧版本回退；回退不能直接换回旧库而丢失迁移后的新文章。
